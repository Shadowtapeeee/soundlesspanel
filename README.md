# Soundless Server — API + админ-панель в Telegram

Один файл `soundless.js`, база SQLite (встроенный `node:sqlite`), без npm-зависимостей. Node.js ≥ 22.13 (в Docker — Node 24).

## Быстрый старт (Docker)

1. Создайте бота у [@BotFather](https://t.me/BotFather) и скопируйте токен. Свой Telegram ID можно узнать у [@userinfobot](https://t.me/userinfobot).
2. Скопируйте настройки и заполните их:
   ```bash
   cp .env.example .env
   ```
   Обязательно: `BOT_TOKEN`, `ADMIN_IDS`, `PUBLIC_URL`. Для премиум-эмодзи в сообщениях и на кнопках у владельца бота должен быть Telegram Premium. Без него бот автоматически переключится на обычные эмодзи.
3. Запустите:
   ```bash
   docker compose up -d --build
   ```
   `.env` в образ **не копируется**: он передаётся при запуске через `env_file` (или `docker run --env-file .env`). Данные (база, треки, обложки, аватары) лежат в `./data`.

Без Compose:
```bash
docker build -t soundless-server .
docker run -d --name soundless --restart unless-stopped --env-file .env -p 8080:8080 -v "$(pwd)/data:/data" soundless-server
```

Без Docker: `node --disable-warning=ExperimentalWarning soundless.js` (файл `.env` рядом подхватится автоматически). Если сервер работает за корпоративным прокси, добавьте `NODE_USE_ENV_PROXY=1`.

## Подключение приложений

Адрес сервера в интерфейсе приложения не отображается и не вводится пользователем. Он берётся из одного из двух мест:

- поле `"server"` в файле `update.json` репозитория GitHub (приложения читают его при запуске);
- переменная `VITE_SERVER_URL` при сборке приложения (адрес вшивается в сборку).

Для HTTPS поставьте перед сервером Caddy или nginx и включите `TRUST_PROXY=1`. Пример для Caddy:
```
music.example.com {
  reverse_proxy 127.0.0.1:8080
}
```
`CDN_URL` позволяет отдавать файлы каталога (аудио, обложки) через CDN. Сервер поддерживает HTTP Range, ETag и Last-Modified.

## Вход и регистрация

- **Логин и пароль** с защитой от ботов: перед входом и регистрацией устройство решает криптографическую задачу (proof-of-work). Сервер выдаёт задачу, подписанную `CAPTCHA_SECRET`, проверяет решение и не принимает его повторно. Сложность задаётся `CAPTCHA_DIFFICULTY`.
- **Google**: создайте OAuth-клиент типа «Веб-приложение» в Google Cloud Console и укажите `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`. Разрешённый адрес перенаправления: `${PUBLIC_URL}/api/auth/google/callback` (`PUBLIC_URL` должен быть доступен по HTTPS). Пользователь может войти через Google, зарегистрироваться или привязать Google к существующему аккаунту в настройках. Есть быстрый повторный вход.
- Если пароль забыт: войти через привязанный Google и задать новый пароль, либо администратор сбрасывает пароль в боте.

## Админ-панель в Telegram

Бот отвечает только администраторам из `ADMIN_IDS`; остальные пользователи получают отказ. Команда `/start` (или `/admin`) открывает инлайн-меню, которое редактируется на месте:

- **Статистика**: пользователи, онлайн, прослушивания, каталог, Google-аккаунты, подписчики Aura, топ треков и артистов.
- **Пользователи**: поиск, карточка пользователя, блокировка, верификация, сброс пароля, завершение сессий, удаление.
- **Aura**: выдача подписки на 30, 90 или 365 дней либо бессрочно, продление и отключение. Список подписчиков.
- **Каталог**: отправьте боту аудиофайл (MP3, M4A, FLAC, OGG), и он появится в приложении. Название, исполнитель и обложка берутся из файла. Можно отредактировать поля, обложку и текст (LRC с таймкодами включает караоке). Нормализация громкости и волна трека считаются через ffmpeg.
- **Рассылка**: объявление-баннер на главной в приложении или сообщение в Telegram всем, кто запускал бота.
- **Настройки**: регистрация открыта или закрыта, технические работы, каталог Audius, уведомления о новых регистрациях.

> Облачный Bot API отдаёт ботам файлы размером до 20 МБ. Для больших файлов (FLAC) поднимите [локальный Bot API сервер](https://github.com/tdlib/telegram-bot-api) и укажите его в `TELEGRAM_API`.

## Soundless Aura

Подписку выдаёт администратор в боте. Все права проверяются только на сервере. Флаги из приложения не учитываются, а при недостатке прав сервер отвечает `402 aura_required`.

| Возможность | Бесплатно | Aura |
|---|---|---|
| Значок с бликом, расширенный профиль (темы, свечение, статус, закреплённый трек) | — | ✓ |
| Анимированные аватары, баннеры и обложки (GIF/APNG/WebP) | — | ✓ |
| Миксы | волна, настроения | + Aura Blend, «Глубже», более широкая волна |
| Плейлисты по текстовому описанию | 3 в сутки | без ограничений |
| Перевод текстов песен | 40 за 10 минут | 400 за 10 минут, подсветка «Аура» |
| Офлайн-хранилище на устройство | 1 ГБ | 10 ГБ |
| Синхронизация устройств (настройки, очередь) | — | ✓ |
| Статистика | 30 дней | год, тепловая карта, жанры, источники |
| Комнаты совместного прослушивания | до 5 человек | до 10 человек |
| Достижения | базовые | + расширенные |
| Ранний доступ (релизы с пометкой `early`) | — | ✓ |

`AURA_CONTACT` — ссылка, куда приложение ведёт пользователя за подпиской (канал, чат поддержки, страница оплаты).

## Источники музыки

- **Каталог сервера**: треки, загруженные администратором. Качество 192, 256 и 320 kbps перекодируется через ffmpeg на лету и кэшируется. «Максимальное» отдаёт оригинал.
- **Deezer** (открытый API, без ключа): поиск, метаданные, обложки, похожие артисты, чарты, подборки по настроению. Если полная версия трека не найдена в каталоге, SoundCloud или Audius, играет официальный 30-секундный фрагмент, и приложение помечает его как «Превью».
- **SoundCloud** (официальный API): поиск и полные треки. Нужны `SOUNDCLOUD_CLIENT_ID` и `SOUNDCLOUD_CLIENT_SECRET` зарегистрированного приложения SoundCloud.
- **Офлайн-загрузка SoundCloud**: сервер сначала скачивает MP3 через `yt-dlp`, а при ошибке берёт прогрессивный или HLS-поток SoundCloud. В Docker-образе установлены `yt-dlp` и `ffmpeg`; для запуска вне Docker путь к `yt-dlp` задаётся через `YTDLP_PATH`.
- **Spotify** (официальный Web API): поиск и метаданные. Нужны `SPOTIFY_CLIENT_ID` и `SPOTIFY_CLIENT_SECRET` (бесплатное приложение в Spotify for Developers). Воспроизведение через Spotify API невозможно, поэтому трек сопоставляется с доступным источником.
- **Audius**: открытый каталог независимых артистов (полные треки, без ключа).
- **Тексты**: LRCLIB, с пословной синхронизацией, где она есть.
- **Перевод текстов**: `TRANSLATE_PROVIDER=mymemory|google|libre|deepl`.

Без ключей SoundCloud и Spotify сервер работает на каталоге, Deezer и Audius. Источники с ключами включаются автоматически.

Поиск кэшируется на 5 минут и разбит на страницы. Внешние запросы повторяются с экспоненциальной задержкой.

## Обновления приложений

Установщики публикуются во вложениях GitHub Releases. Приложения проверяют последний релиз (включая бета-версии) и `update.json` в ветке `main`. Релизы, у которых в теге или названии есть `early`, видят только подписчики Aura с включённым ранним доступом: их отдаёт сервер (`GET /api/updates/early`).
